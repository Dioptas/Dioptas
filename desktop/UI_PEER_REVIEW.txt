## New findings

All of these come from reading the code; I didn't run any of them.

- **P1. Undo/Redo and image loads can still replace pending drafts without asking (minor).**
  - **Where:** `geometryDraft.ts:65-67` and `useCalibrationFitDraft.ts:49-56` rebuild the drafts whenever the model geometry or parameters change. The confirmation guard covers only the three source commands.
  - **Trigger:** Calibrate, then type a manual geometry draft without applying it. Click outside the field and press ⌘/Ctrl+Z. The undo of the calibration restores the earlier geometry and the typed draft disappears without a prompt.
  - **Judgement:** undo plausibly implies replacement, so I treat this as minor friction, not a defect.
- **P2. Bound errors show raw constants and no unit (minor).** `numericDraft.ts:16-19` together with `fitEnergyLimits` produces "Enter a value of at least 1.239841984332." The wavelength and distance messages also omit Å and mm.
- **P3. The Save tooltip's fallback text can be inaccurate (minor).** When Save is disabled only because nothing is calibrated yet or a command is running, the tooltip still reads "Save the current applied geometry…" (`App.tsx:2734-2742`).
- **P4. The confirmation doesn't say which drafts would be lost (optional).** `ConfirmDraftReplacement.tsx:23-26` doesn't say whether the drafts are geometry, fit seeds or integration options.
- **P5. The short Batch axis title drops "0-based" from view (optional).** At short heights it reads "Index". The toolbar's "Index 0 · 1 of 6" and the ARIA description keep the meaning.
- **P6. The text-scale tokens are defined in two files (minor).** `style.css:13-15` and `:1720-1722` duplicate the base and Larger values that `uiTheme.css` also sets.
