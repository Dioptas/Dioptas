# Independent UI design review: Dioptas desktop GUI at `cc3c8704`

This was a read-only review; I changed no files. I formed my scores before opening `UI_DESIGN_REVIEW.json`, `index.html` or any peer scores, and I still haven't opened them. The headless `after/report.json` and `webkit/report.json` both record `completed: true`, `failure: null`, `errors: []` and empty automated `accessibility` arrays. Their `manualAccessibilityChecks` are axe "incomplete" items that still need a human check: color contrast that axe couldn't resolve over gradients or images, `th-has-data-cells` on the empty `.phase-table`, and `aria-controls` on the icon-picker trigger. These count as missing evidence, not as passes or failures.

## (3) Prioritized findings

### Confirmed code or design defects

**F1. Fit starting-value fields coerce input to 0 (validation, precision).**
- **Where:** `CalibrationExtras.tsx:233-241`. The controlled input stores `value: Number(e.target.value)`. A number input reports `""` for empty or partial text such as "-", `Number("")` is 0, and React then writes "0" back into the field.
- **Trigger:** In Calibration › Fit, select Rotation 1 and type `-0.01`. The leading "-" becomes "0". Clearing Distance before retyping stores a 0 mm seed, which goes into the next Calibrate run.
- **Fix:** Keep the draft as a string with the `ScientificNumberInput` pattern. Mark it invalid and block Calibrate until it's finite.
- **Scope:** I read this from the code path. I didn't run it.

**F2. PONI units differ for the same quantity (precision, consistency).**
- **Where:** `CalibrationExtras.tsx:23-24` uses mm; `geometryDraft.ts:6-7` uses m. Visible side by side in manual-geometry.png and calibration-fitted.png.
- **Trigger:** A user copies PONI 1 from Validate (0.0853712 m) into the Fit seed (mm). The value is off by 1000×.
- **Fix:** Pick one display unit, probably mm next to Distance in mm, and convert on the stored side.

**F3. Batch dock toolbar clips its window actions at 1000×760 (responsive, navigation).**
- **Where:** `batch.css:55-71`. `.batch-series-toolbar` is a non-wrapping flex row, its children are `flex: 0 0 auto`, and the parent panel has `overflow: hidden`.
- **Evidence:** batch-compact.png and integration-compact-large.png show "Phases" cut off and no Collapse, Detach or Hide buttons. `batch-compact.aria.yml:48-51` shows they still exist in the DOM.
- **Why the audit missed it:** its "fits 1000×760" check reports `overflow: false` because the clipping container hides the overflow.
- **Fix:** Wrap the toolbar, move overflow into a menu, or shrink the folder label first.

**F4. The manual geometry dialog has its own draft, and any dismissal discards it (workflow, recovery, dialogs).**
- **Where:** `GeometryEditor.tsx:198` vs `App.tsx:299` and `App.tsx:2737-2748`. Dismissal paths are `Dialog.tsx:117-129` (backdrop), Escape and the X button.
- **Trigger:** Type 10 geometry values, then accidentally click outside the dialog. Everything is lost, with no prompt. Separately, edits made in the Validate editor don't appear in the dialog.
- **Fix:** Pass the App-level `geometryDraft` into the dialog, or confirm before dismissing when the draft is dirty.

**F5. Fit seed values aren't labelled as seeds (scientific context).**
- **Where:** `CalibrationExtras.tsx:186, 219-225`. The headings read "Parameters" and "Value".
- **Trigger:** Fit shows 200 mm while the model or dialog shows 1000 mm (manual-geometry.png). The user can't tell which geometry is the current one.
- **Fix:** Rename to something like "Starting values" and/or add a provenance line in the Fit tab.

**F6. `CommitField` frame input accepts clearing and has no range (validation).**
- **Where:** `IntegrationView.tsx:180-197`.
- **Trigger:** Clear the "Frame (1–N)" field and tab away. It commits frame 0.
- **Fix:** Keep a string draft, add `min={1}` and `max={frames}`, and revert on an invalid blur.

**F7. Smaller confirmed polish issues:**
- The "DYNAMIC MASKING PLUGINS" heading is uppercase, unlike other headings (`MaskPanel.tsx:336`).
- The directory path truncates its meaningful tail (`integrationFileControls.css:64`). Ellipsizing from the start would fix it.
- The cake ring label "15" is clipped at the plot edge (calibration-validate.png).
- Toolbar symbols `AA`, `A`, `|` have no text near the plot (`ShortcutReference.tsx:131-148`). They have hover titles, but the meaning is only explained in the help dialog.

### Missing empirical evidence (not defects)

- No screen-reader run (VoiceOver or NVDA). All accessibility evidence is headless axe plus aria snapshots.
- Native contrast for the axe "incomplete" nodes hasn't been resolved. Many sit over gradient or image backgrounds, including mode rail labels and calibration section tabs.
- No native window-manager checks: Tauri multi-window focus, detached Batch/Map/Phase windows on Windows or Linux, high-DPI square-pixel rendering.
- No timing data for perceived responsiveness on large detectors or long batch series.
- No user testing on how learnable the toolbar symbols are.

### Optional enhancements (within your constraints)

- Pick a default legend position that avoids the curve maximum and cursor labels. This keeps the movable in-plot legend and adds no header.
- Show the next undo/redo action as text, not only in a tooltip.
- Consider requiring a focused plot for Enter → integrate, or show a hint for it, since it is a broad global key.
