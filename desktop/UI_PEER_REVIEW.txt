## Remaining defects

**D1. Batch numbering is consistent only in the docked view.** Severity: minor to moderate.
- **Evidence:**
  - The docked header reads "Index N · k of n" (`BatchView.tsx:263`).
  - The detached window footer still reads `Frame ${batch.selected} · name` (`DetachedBatchWindow.tsx:149`). `batch-normalization.png` shows "Frame 0 · series_1.tif".
  - The heatmap readout labels the same 0-based value "Frame" (`BatchHeatmap.tsx:329`).
  - Integration shows "Frame (1–N)" (`IntegrationView.tsx:109`).
  - The detached navigator says "Index · 6/6 loaded" (`BatchControls.tsx:297`). It has no ordinal, and "6/6" is easy to read as the position.
- **Impact:** in the detached window the same image is "Frame 0" there but "Frame 1" in Integration, and "series_1" in its file name. Your decision to keep the zero-based index is respected; the problem is that these places still use the word "Frame" for it.

**D2. The color-scale legend splits apart at compact width.** Severity: minor.
- **Evidence:** `.color-scale-legend` uses `flex-wrap: wrap` and pushes the label to the left with `margin-right: auto` (`uiTheme.css:196-213`).
  - In `map-compact.png` the max value "95575" and "linear" wrap to the next line on the left, away from the white end of the bar.
  - In `map-compact-large.png` the min value "93604" sits on its own line above the bar.
- **Impact:** low and high limits are no longer next to their ends of the bar. That is the reading the legend exists for.

**D3. Plot text ignores the "Larger" text setting.** Severity: minor.
- **Evidence:** only CSS, App and the detached windows use the text-size setting; the pattern, raster and heatmap canvas code doesn't. In the compact screenshots, tick labels, axis titles and plot legends are the same pixel size at Standard and Larger.
- **Impact:** the most important scientific text (2θ ticks, intensity labels) stays small for the users who chose larger text.

**D4. The Phase editor gives two different statuses.** Severity: minor.
- **Evidence:** in `phase-editor.png` the header says "Loaded material" but the footer says "Saved", while the orange primary Save button is enabled.
  - The footer shows "Saved" whenever `data.filename` is set (`PhaseEditor.tsx:1062`).
  - Save is enabled because `canSaveCurrent` is false (`:1089`).
- **Impact:** for an unchanged JCPDS file, "Saved" next to an active primary Save suggests there is something left to save, or that it was already saved in a format it wasn't.

**D5. Legends and range labels still print ASCII minus signs and `e` notation.** Severity: minor.
- **Evidence:** `scientificValue` returns `String(Number(...))` (`ScientificNumberInput.tsx:5-6`). Only the input preview swaps in a real minus sign (`:36`). The color legend (`ColorScaleLegend.tsx:29,34`) and the Map ROI range (`ScanMapPanel.tsx:118`) use the raw string. "4.422507e-10" also appears in the Rotation 3 field in `calibration-fitted.png`.
- **Impact:** negative or very small limits look different from the inputs, and "-0.5–1.2" is hard to tell apart from a range.

**D6. The sidebar truncates the app's own example action name.** Severity: minor.
- **Evidence:** "Inspect detector file" becomes "Inspect detect…" in the sidebar and its preview (`settings-custom-action-editor.png`), and "Inspect detecto.." in `map-compact-large.png`.
- **Impact:** the bundled example breaks the editor's own advice ("Aim for one short word…").

**D7. Small hierarchy and visualization issues.** Severity: minor.
- **"Click —" outside plots:** the green "Click —" readout also shows in Settings (`settings-integration.png`; `App.tsx:2873` only checks the mode). It's an accent-colored label with nothing to read.
- **Duplicate legend names:** in `integration-overlay-confirm.png` the plot legend shows "CeO2_Pilatus1M" twice, white and green. The table distinguishes "Original · …", but the legend doesn't.
- **Legend over data:** in `map-compact.png` the pattern legend sits on top of the curve maximum and the phase marker "A".

**D8. Structure (scored under maintainability, not a bug).** `App.tsx` is 2,940 lines and `PhaseEditor.tsx` is 1,112. Batch normalization still sends 1-based arguments to `batch_normalize` and 0-based ones to `batch_normalization_settings` (`BatchControls.tsx:110-112` vs `:198`).
